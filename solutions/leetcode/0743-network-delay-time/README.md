- 코드: [Solution.java](./Solution.java)

## 접근
방향 그래프의 인접 리스트와 최소 우선순위 큐를 이용하는 다익스트라 풀이다. 시작 정점의 거리를 0으로 두고 최단 거리로 꺼낸 정점을 확정한 뒤 인접 간선으로 거리를 갱신한다. 모든 정점의 최단 거리 중 최댓값이 전체 신호 전파 시간이며, 도달 불가능한 정점이 있으면 -1이다.

가중치가 0 이상이므로 최초 확정 시점의 거리가 최단 거리다. 현재 입력 제한에서는 유한 최단 거리가 최대 99 × 100 = 9900이므로 int를 사용한다. 큐에는 유한 거리만 넣으므로 INF에 간선 비용을 더하지 않는다. 범용 템플릿은 long 사용과 거리 상한 검토가 필요하다.

## visited 버전으로 변경
사용자 요청에 따라 최종 코드는 visited 방식을 저장한다.

| 방식 | 생략 대상 |
|---|---|
| cur.w > dist[cur.to] | 더 짧은 경로가 발견된 오래된 거리 정보 |
| visited[cur.to] | 이미 최단 거리를 확정하고 인접 간선을 처리한 정점 |

둘 다 올바른 구현이다. visited가 항상 더 빠르다는 성능 개선으로 단정하지 않는다. visited 배열은 O(V) 공간을 추가 사용한다. 방문 표시는 큐에 넣을 때가 아니라 최소 거리로 꺼낸 뒤 수행한다.

## 복잡도
- 시간: O(V + E log(E + 1)), 중복 삽입형 우선순위 큐 기준
- 추가 공간: O(V + E), 인접 리스트와 큐 포함

## 수정 및 학습 기록
- 마지막 반복문의 dist[t]를 dist[i]로 수정했다.
- import, 클래스·메서드 선언과 한국어 주석을 추가하고 사용자 최종 로직을 유지했다.
- 변수명 오타는 단순 실수로 복습에서 제외한다.
- 다익스트라 코드의 큰 틀을 참고한 학습으로 기록한다. 전체 해설 의존이나 구체적인 개념 부족은 추측하지 않는다.
- 사용자 정답 확인에 따라 최초 통과를 체크한다. 독립 재풀이는 별도 확인 전까지 미완료로 유지한다.
- 새 문제 우선 요청에 따라 현재 사이클 중 복습은 자동 배정하지 않는다.

## 검증
기본 전파, 도달 불가, 더 짧은 우회 경로, 비용 0, 한 정점 사례의 코드 흐름을 검토했다. 로컬 실행을 시도했으나 환경에 javac가 없어 컴파일·실행 검증은 수행하지 못했다. LeetCode 채점 정답은 이후 사용자 확인에 근거한다.
