## 접근 방법

합이 target이 되는 서로 다른 두 원소의 인덱스를 찾는다. HashMap에 앞서 방문한 원소의 값과 인덱스를 저장한다.

현재 값 nums[i]와 더해서 target이 되는 값은 `target - nums[i]`이다. 이 값이 맵에 있으면 저장된 인덱스와 현재 인덱스를 반환한다. 없다면 현재 값과 인덱스를 맵에 넣고 다음 원소를 확인한다.

조회 후 저장하므로 같은 인덱스를 두 번 사용하지 않는다. 정답이 존재하는 문제 조건에서는 반복문 안에서 반환하며, 마지막 빈 배열 반환은 정답을 찾지 못했을 때의 처리다.

## 시간·공간복잡도

- 시간: 평균 O(N). HashMap의 조회와 삽입은 평균 O(1)이다.
- 공간: O(N). 방문한 값과 인덱스를 저장한다.
- N의 의미: 배열 nums의 길이.

## 오답과 반례

- 공유한 코드에서 논리 오류는 발견하지 않았다. import와 들여쓰기를 정리해 저장했다.
- 주의할 점: 현재 값을 먼저 저장하면 같은 인덱스를 재사용할 수 있으므로 조회를 먼저 한다.
- 검토 예시: `[3, 3]`, target `6`에서는 첫 번째 3을 저장한 뒤 두 번째 3에서 찾아 `[0, 1]`을 반환한다.
- 검토 예시: `[3, 2, 4]`, target `6`에서는 첫 번째 3을 자기 자신과 짝짓지 않고 `[1, 2]`를 반환한다.

## 핵심 정리

두 수의 합 문제에서는 현재 값의 짝인 `target - 현재 값`을 맵에서 찾는다. 인덱스를 반환해야 하므로 값과 인덱스를 함께 저장하고, 같은 원소를 재사용하지 않도록 조회 후 저장한다.
